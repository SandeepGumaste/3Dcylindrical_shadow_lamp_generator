# Shadow wall base plate Implementation Plan

> Owner request (2026-10-20): "Add a base like in the MakerWorld Light Shadow Art Generator" (OpenSCAD model: a flat plate under the wall, 3 mm thick, with a 12.5 mm centre hole for the light and two 8.1 x 2.1 mm magnet pockets 12 mm either side of the centre, on the underside). Built on `feat/shadow-wall-mode`. Spec for the mode: `docs/superpowers/specs/2026-10-20-shadow-wall-mode-design.md` (this plan amends it). Test-first; focused test while iterating, full `npx vitest run` + `npx tsc --noEmit` once before each commit; NO Playwright or browser; do not push; no subagents.

## Design (rulings)
- Base is optional (`base: boolean`, default true) and sits under the wall exactly like Tealight's floor (`addFloor` in `src/geometry/tealightShade.ts`): the wall's z coordinates stay measured from the TOP of the base (z = 0), the plate occupies z in [-T, 0] while building, and every vertex is shifted up by T at the end so the model rests on z = 0 (the ground).
- `lightHeight` stays "above the top of the base". The ground (where the shadow lands) is the underside of the base, T lower, so the table position of wall node (i, z) becomes `q * (hf + T) / (hf - z)` (T = 0 without a base). This applies to the field sampling, the adaptive row spacing, the outside-reach warning and `groundRadius`/preview (`groundRadius` is the image half-size, unchanged).
- Plate construction (watertight, shared vertices; the shell is built with `skipBottomBorder: true`, which returns `bottomInner` / `bottomOuter` vertex rings): plate top face at z = 0 = the region inside the shell's inner bottom ring minus the centre hole; plate side face from `bottomOuter` down to a new rim ring (same xy, z = -T); plate underside z = -T = the rim polygon minus the centre hole minus the magnet pockets; centre-hole wall (z -T..0); each pocket: wall from z = -T up to -T + depth and a ceiling disc. The annulus between the two shell rings at z = 0 is interior and gets no face. Faces with holes are triangulated with `cdt2d(points, edges, { exterior: false })` using the ring vertices themselves (no new boundary vertices), as `src/geometry/box/perforatedWall.ts` does.
- Centre hole: circle of `baseHoleDiameter` (default 12.5 mm) at the footprint centre; magnet pockets: two circles of `magnetDiameter` (8.1) at (0, +magnetOffset) and (0, -magnetOffset) (default 12 mm), depth `magnetDepth` (2.1) from the underside; `magnetHoles: boolean` default true.
- The solid foot above the plate must stay: the foot height becomes max(existing foot, 2 mm) measured from the plate top (it already is >= 3 mm), so no change there.
- Validation: `baseThickness` 0.4 to 10; hole diameter at least 4 and at most (smallest inner radius - 2) * 2; with magnets: pocket circles lie at least 1 mm inside the inner outline, at least 1 mm clear of the centre hole and of each other, depth at most baseThickness - 0.4. Rectangle/ellipse that are too small fail with a clear message.

### Task A: plate mesh
**Files:** create `src/geometry/shadowWall/base.ts`, `src/geometry/shadowWall/__tests__/base.test.ts`.
```ts
export interface BaseSpec { thickness: number; holeDiameter: number; magnets: boolean; magnetDiameter: number; magnetDepth: number; magnetOffset: number }
/** Adds the plate to `mb` (z in [-thickness, 0]); `bottomInner`/`bottomOuter` are the shell's bottom rings (xy read from mb.positions). Returns nothing; the mesh stays one closed manifold with the shell. */
export function addBase(mb: MeshBuilder, bottomInner: Int32Array, bottomOuter: Int32Array, spec: BaseSpec): void;
export function validateBase(spec: BaseSpec, outline: Outline): string[];
```
- [ ] Tests first: build a plain shell (rectangle 80x80 r10 and ellipse 90x70, the all-black or blank image field is fine via `generateShadowWall` internals or a tiny hand-built `buildShell` call) with `skipBottomBorder`, add the base, and assert `checkMesh` watertight with positive volume, no degenerate triangles; vertex bounds z in [-T, top]; the plate volume equals area(outline) * T - hole - pockets within 1 % (use the signed volume difference with and without magnets and without a hole); with magnets off the underside has no pocket vertices; hole and pockets are where specified (a vertex ring at the hole radius, pocket centres at (0, ±offset)); `validateBase` messages for each failing case (hole too big/small, pockets outside, overlapping, depth too deep, thickness out of range) and empty for the defaults on 80x80 r10.

### Task B: integrate
**Files:** modify `src/geometry/shadowWall/shadowWall.ts` (params, defaults, validation call, table-position scale, `generateShadowWall` skipBottomBorder + addBase + z shift, topZ/lightZ semantics, warnings), `src/workers/shadowWallCompute.ts` (`lightZ`, `topZ` account for the shift), `src/components/ShadowWallPanel.tsx` (a Base group: checkbox, thickness, hole diameter, magnet checkbox, diameter, depth, offset; disabled states), tests in `field.test.ts`, `mesh.test.ts`, `src/workers/__tests__/shadowWallCompute.test.ts`; `ARCHITECTURE.md` + the spec (a short Base paragraph).
- Params added to `ShadowWallParams` with defaults: `base: true, baseThickness: 3, baseHoleDiameter: 12.5, magnetHoles: true, magnetDiameter: 8.1, magnetDepth: 2.1, magnetOffset: 12`.
- Ground drop G = base ? baseThickness : 0: table position `q * (hf + G) / (hf - z)` everywhere the code uses `hf / (hf - z)` (field luminance sampling, row spacing `dz = cell * (hf - z)^2 / (dMax * (hf + G))`, the reach warning's `hf / (hf - (height - RIM))`). With the base off the numbers are exactly unchanged (existing tests stay green).
- `generateShadowWall`: when `base`, build the shell with `skipBottomBorder: true`, `addBase`, then add `baseThickness` to every z (like Tealight). The result `geometry`/`field` stay in wall coordinates; `lightZ = hf + G` and `topZ = height + G` in the compute output (the preview stands the model on z = 0 and puts the light hf above the base top).
- [ ] Tests first: with the base off all previous mesh tests unchanged; with it on: watertight, bbox z from 0 to height + T, the base footprint equals the wall footprint, a Batman-like image mapped with the ground drop lands at the scaled table position (assert the field's table-position scale (hf+T)/(hf-z) with a hand-computed node), pockets/hole present in the mesh (vertex at (0, 12, 0) region etc.), invalid base params surface through `validateShadowWallParams`, the compute output's lightZ/topZ, STL length formula still holds.
- [ ] Panel: Base group with the controls above (read `ShadowWallPanel.tsx`; same `Num`/`Check` building blocks); no new dependencies.
- [ ] Run the full suite, tsc and `npx vite build` (VITE_SITE_URL=https://example.com, outDir in the scratchpad), commit `feat: shadow wall base in the model, ground-plane aware mapping, base controls`.
